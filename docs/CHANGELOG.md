# Changelog

Implementation changes, one line per finished task. Format: `- FEAT-nnn-Tnn: what changed`.

## [Unreleased]
- FEAT-004-T17: TempFiles (data/temp_files.dart) writes only the final file to <app cache>/exactsize_out/<32 random hex>.jpg|png (path_provider 2.1.6, pinned), removes a partial file and raises TempWriteException on a write error, and sweeps the folder; main() sweeps it at every start (FR-20). CompressionService.compress (data/compression_service.dart, deferred from T16) runs the CompressionRunner, writes the file and returns CompressionSuccess, or CompressionFailure with WRITE_FAILED (closest = the file size) when writing fails; a cancel that lands during the write deletes the file and returns CANCELLED. Tests (host): one randomly named file on success inside the cache, empty folder after failure and cancel, WRITE_FAILED with no file when the folder path is blocked, sweep removes planted leftovers; on the S23 Ultra the folder is inside the app's private cache. T16 addendum: on the 2 GB emulator the profile smoothness check shows 11 frames with 10 missed raster budgets (worst raster 148 ms) because the headless emulator renders in software; informational only, the phone showed none.
- FEAT-004-T16: CompressionRunner (data/compression_runner.dart) runs one request on a worker isolate that gets the NativePixelBuffer address (ADR-003, no pixel copy); FR-1 layout check (size, channels 3|4, stride = width × channels, enough bytes) before any encode; progress (pass, 10) and the result share one port, so progress never arrives late; cancel flag in native memory checked before every pass; the result returns with Isolate.exit (no copy); the buffer is freed on success, failure, cancel and error; encoder init failure → OUT_OF_MEMORY_HANDLED. NativePixelBuffer (owning allocate / non-owning view, debug leak counter) and a stride field on PixelBuffer; ffi is now an app dependency. CompressionService.compress moves to T17, because a success needs the temp file. Tests (host, 2 GB emulator API 36.1, S23 Ultra): monotonic progress ending at the pass count, cancel stops before the search finishes (an exact "within one pass" count is not observable from the main isolate on a fast phone, since progress messages are in flight), cancel before the first pass encodes nothing, RGBA flattened with notice, PNG through the runner, layout mismatches rejected with no pass, leak counter 0 after 100 mixed runs. UI smoothness (integration_test/runner_jank.dart, profile, --no-dds), informational: on the S23 Ultra worst frame build 0.5 ms and raster 1.3 ms with no missed frames, but only 3 frames were captured, so this is weak evidence.
- FEAT-004-T15: domain planPng (png_plan.dart): one lossless encode and the final gate; too big → PNG_ABOVE_MAX with one JPEG probe at q40 (config A) setting jpegWouldFit, run after a prepareForJpegProbe callback so the runner can flatten alpha first; too small → PNG_BELOW_MIN with no padding; the format never changes on its own. Data DartPngEncoder: image package PngEncoder level 9, RGB or RGBA kept, pHYs only with a DPI, no iCCP/eXIf/text chunks. TestPixels moved to test_support for reuse. Tests: in range, above max with probe fit true and false, below min, lossless round trip for RGB and RGBA, pHYs adds exactly 21 bytes, no metadata chunks.
- FEAT-004-T14: domain flattenForJpeg (flattener.dart), FR-12: composites RGBA onto white with out = (c·a + 255·(255 − a) + 127) ÷ 255 (round half up) and compacts 4 → 3 channels in the same buffer in one forward pass; returns transparencyFlattened only when the input had transparency; RGB input is untouched. The domain PixelBuffer interface gains `bytes` (a view of the pixel memory) and markAlphaRemoved() for the native buffer in T16. Tests: exact RGB for alpha 0, 1, 128, 254, 255 (worked by hand), channels 3, same buffer object and no new pixel allocation (counting test buffer), opaque RGB untouched, opaque RGBA compacted without a notice.
- FEAT-004-T13: domain planJpeg (jpeg_plan.dart) chains search → padding → final gate (FR-6) on the exact bytes to be written and returns ReadyToWrite (bytes plus quality, subsampling, Huffman flag, padding bytes, notices) or PlanFailed (CompressionFailure); the data layer writes the temp file and builds CompressionSuccess (T17). Notices: narrowRange whenever the FR-4 fallback window is used (also on failures), paddingAdded when padding was spliced in. Every failure carries closestBytes and direction; TOO_DEGRADED no longer can have a null closest size; InvalidTarget.failure gives INVALID_TARGET without size or direction. size_gate_property_test.dart: 1,000 seeded random targets and curves; every success inside its window and ≥ q40, every failure explained, every padded success disclosed, ≤ 10 passes, and all three outcome kinds occur.
- FEAT-004-T12: domain padJpeg (jpeg_padder.dart), FR-8 lever 4: COM segments spliced right after the JFIF APP0, payload all 0x20, segments of 4 to 65,537 bytes (a remainder under 4 borrows from the segment before), target min(lo + min(1024, (hi − lo) ÷ 2), hi) with at least 4 bytes; under 4 bytes of room → BELOW_MIN, or NO_FIT in the jump case. ByteWindow.bytes() added for exact-byte windows. Tests: pad amounts 4, 5, 65,537, 65,538, 65,540, 200,000 with parsed segment sizes; COM right after APP0 and EOI last; decoded pixels identical to the unpadded file; payload all 0x20; target rule; room 3 vs 4; identical bytes on repeat.
- FEAT-004-T11: searchJpeg now covers FR-8 levers 1–3 and the OQ-12 jump case with configs A (4:2:0 + optimised), B (4:4:4 + optimised), C (4:4:4 + standard Huffman), baseline only. Floor path: B@100 → quality search in B (pad that file if it lands below the floor) or C@100 (pad C@100 if still below, pad B@100 if C jumps over the ceiling). Jump case: B and C at the same quality, else the largest file under the ceiling goes to padding with jumpCase = true. Cache keyed by (config, quality); only the best file per config and the largest file under the ceiling keep their bytes. Tests: one per branch, A → B → C order checked from the fake encoder log, all within 10 passes.
- FEAT-004-T10: domain searchJpeg (size_search.dart), main path with config A (4:2:0, optimised Huffman): A@100, binary search for the largest q in [qFloor = 40, 99] with size ≤ hi, then q+1 and q+2 for non-monotonic curves, highest fitting q wins; nothing ≥ q40 fits → A@1 decides ABOVE_MAX or TOO_DEGRADED; hard cap of 10 passes with a closest-size fallback; per-quality size cache, bytes kept only for the best candidate. Outcomes SearchFit / SearchBelowWindow (hand-off to the T11 levers and T12 padding, with the jump-case flag) / SearchFailure. Tests on scripted curves: monotonic, non-monotonic dip, TOO_DEGRADED, ABOVE_MAX, no min (AC-8.2), and a sweep of 4 curves × 55 targets staying ≤ 10 passes and never below q40.
- FEAT-004-T09: domain ByteWindow (FR-3/FR-4: lo = min×1024, hi = max×1000, narrow fallback lo = min×1000, no min → lo = 0, inclusive contains) and validateTarget (FR-16, PRD section 8) returning ValidTarget or InvalidTarget with a TargetMessage key for the ARB strings in T19. Interpretation recorded: a min of 0 or below gets the "Enter a valid size in KB" message (the PRD only says min must be ≥ 1); text is trimmed; format accepts jpeg/png case-insensitively. Tests cover every section 8 row, the 1.024 boundary (125/128 KB fits, 126/128 KB is narrow) and that no encoding happens on INVALID_TARGET.
- FEAT-004-T08: domain result model (lib/features/compression/domain): OutputFormat, Reason (12 codes in PRD section 5 order, PRD spelling in `code`), Notice, Direction, sealed CompressionResult with CompressionSuccess and CompressionFailure (no file path), CompressionRequest, a domain PixelBuffer interface (native implementation in T16), and the Encoder interface (bound to one request's pixels and DPI; TurboJpegEncoder plus the PNG encoder are composed into it in T15/T16). test/features/compression/fake_encoder.dart scripts size curves per (subsampling, Huffman, quality) and records calls.
